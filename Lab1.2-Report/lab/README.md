# Шаблон отчёта по лабораторной работе

Отдельный от курсовых/дипломных (`cource/`, `common/`) шаблон, рассчитанный
на то, чтобы для каждой новой лабораторной работы менять только:
`lab/lab_vars.tex`, `lab/sections/*.tex`, картинки в `lab/pictures/`, код в
`lab/code/` и диаграммы в `lab/diagrams/src/`. Общий `preamble.tex` (шрифты,
поля, подписи рисунков/таблиц/листингов, список литературы) переиспользуется
как есть.

## Структура

```
lab/
  lab_report.tex        главный файл — компилировать именно его
  lab_vars.tex           переменные: номер работы, тема, студент, группа...
  lab_preamble.tex        доп. настройки: код-листинги, plantuml-диаграммы,
                          заголовки блоков, сквозная нумерация рисунков и т.д.
  lab_title.tex           титульный лист (использует переменные из lab_vars.tex)
  sections/
    goal.tex              Цель / Задание
    body.tex              основное содержимое — см. примеры ниже
    conclusion.tex         Выводы
  pictures/               скриншоты и картинки для \includegraphics
  code/                   исходники для листингов кода (\codelistingfile)
  diagrams/
    src/*.puml             исходники диаграмм PlantUML
    generated/*.png         собранные картинки (создаётся build.sh, не редактировать руками)
    build.sh                скрипт сборки .puml -> .png
```

## Быстрый старт

```bash
make lab            # соберёт диаграммы PlantUML и скомпилирует PDF
# или по отдельности:
make lab-diagrams   # только пересобрать диаграммы
make lab-pdf         # только пересобрать PDF (диаграммы не трогает)
make lab-clean       # удалить служебные файлы сборки
```

Результат — `lab_report.pdf` в корне репозитория.

Компиляция требует ключ `-shell-escape` (уже прописан в `Makefile`), так как
подсветка кода (пакет `minted`) под капотом вызывает `pygmentize`. Если
компилируете вручную, а не через `make`, не забудьте этот ключ:

```bash
bash lab/diagrams/build.sh
latexmk -pdf -shell-escape lab/lab_report.tex
```

## Как заполнить отчёт под конкретную работу

1. Впишите номер, тему, дисциплину, ФИО и т.п. в `lab/lab_vars.tex`.
2. Впишите цель/задание в `lab/sections/goal.tex`.
3. Опишите ход работы в `lab/sections/body.tex` (см. примеры ниже —
   исходный файл уже содержит по одному рабочему примеру каждого элемента,
   их можно копировать и менять).
4. Впишите выводы в `lab/sections/conclusion.tex`.
5. Соберите: `make lab`.

Если отчёт большой и в нём много тематических блоков — можно раскомментировать
`\input{table_of_contents}` в `lab/lab_report.tex`, чтобы добавить оглавление.

## Заголовки

- `\labpart{Название блока}` — жирный отцентрированный заголовок без номера,
  без разрыва страницы, автоматически попадает в оглавление (если оно
  используется).
- `\labpartbreak{Название блока}` — то же самое, но с `\clearpage` перед
  заголовком.
- `\subsection*{Заголовок}` — обычный жирный нецентрированный подзаголовок
  (уже настроен в `preamble.tex`). Если нужна ручная нумерация подзаголовков —
  пишите номер прямо в тексте: `\subsection*{1. Название}`.

Рисунки и таблицы нумеруются сквозным счётчиком (1, 2, 3, ...), а не по
разделам — это специально переопределено в `lab_preamble.tex`, так как в
лабораторных работах (в отличие от курсовых/дипломных) нет нумерованных
`\section`.

## Рисунки и таблицы

Обычные `figure`/`table` окружения, как в `preamble.tex` (подписи уже
стилизованы: «Рисунок N – …» под рисунком, «Таблица N – …» над таблицей).
Скриншоты и картинки кладите в `lab/pictures/`. Пример — в `body.tex`.

Ссылки в тексте — через `\autoref{fig:...}` / `\autoref{tab:...}` /
`\autoref{lst:...}`.

## Листинги кода (пакет `minted`)

Два способа вставить код, оба создают подписанный и пронумерованный
листинг («Листинг N – …»):

**Из файла с исходным кодом:**
```latex
\codelistingfile{python}{lab/code/example.py}{Подпись листинга}{ключ-метки}
```

**Прямо в тексте отчёта:**
```latex
\begin{codelisting}{json}{Подпись листинга}{ключ-метки}
{
  "type": "query"
}
\end{codelisting}
```

Язык (`python`, `json`, `bash`, `cpp`, `sql`, ...) — любое имя лексера
Pygments (`pygmentize -L lexers`).

## Диаграммы PlantUML

1. Опишите диаграмму текстом в `lab/diagrams/src/<имя>.puml` (см.
   `example.puml`).
2. Соберите картинки: `make lab-diagrams` (или `bash lab/diagrams/build.sh`).
   Скрипт кладёт `<имя>.png` в `lab/diagrams/generated/`.
3. Подключите в отчёте:
   ```latex
   \pumldiagram{имя-файла-без-расширения}{Подпись}{ключ-метки}{0.8}
   ```
   Последний аргумент — ширина картинки в долях `\textwidth`.

Скрипт сборки сам ищет, чем рендерить диаграммы (по порядку): переменную
окружения `PLANTUML_CMD`, команду `plantuml` в `PATH`, переменную
`PLANTUML_JAR` (путь к `plantuml.jar`), файл `lab/diagrams/plantuml.jar`,
`~/.local/tools/plantuml.jar`, и в последнюю очередь — Docker-образ
`plantuml/plantuml`. Если ни один вариант не найден, скрипт подскажет,
что установить.

Правьте только файлы в `diagrams/src/*.puml` — файлы в `diagrams/generated/`
перезаписываются скриптом и не предназначены для ручного редактирования.

## Заметки для ИИ-агентов, заполняющих отчёт

- Меняйте только: `lab/lab_vars.tex`, `lab/sections/*.tex`, файлы в
  `lab/pictures/`, `lab/code/`, `lab/diagrams/src/`. Не трогайте
  `preamble.tex`, `lab/lab_preamble.tex`, `lab/lab_title.tex` — это
  инфраструктура, а не содержимое отчёта.
- Каждый новый рисунок/таблица/листинг/диаграмма должен иметь уникальный
  ключ метки (последний аргумент команды), иначе `\autoref` будет указывать
  не туда либо LaTeX выдаст предупреждение о повторном определении.
- После добавления новых `.puml`-файлов обязательно выполните
  `make lab-diagrams` (или `bash lab/diagrams/build.sh`) до сборки PDF —
  иначе `\pumldiagram` не найдёт картинку.
- Сборка не проходит без ключа `-shell-escape`; если запускаете `pdflatex`/
  `latexmk` напрямую, а не через `make lab`, добавляйте этот ключ вручную.
- Собранный PDF стоит визуально проверять (например, командой `Read` над
  итоговым `lab_report.pdf`) — LaTeX не всегда предупреждает о переполнении
  строк, наползающих подписях и т.п.
