\labpart{Выводы}

Семантически лабораторная работа подтвердила утверждение задания о том,
что любой сервер с публичным IP-адресом подвергается непрерывному
фоновому сканированию и подбору паролей вне зависимости от того, что
на нём размещено. Первое обращение к веб-серверу зафиксировано через
несколько секунд после начала записи журнала (18:49:54 UTC), причём
через доменное имя, а не по IP -- то есть публикация сертификата уже
сама по себе делает сервер видимым. За первые 47,6~ч по SSH накопилось
13\,458 неудачных попыток с 64 уникальных адресов ($\approx$283 в час),
из них 71,7\,\% -- под именем \texttt{root}; один адрес дал 52\,\% всех
попыток. Ни один из адресов, замеченных в переборе, не получил доступа,
но единственной причиной этого была стойкость пароля \texttt{root},
поскольку вход \texttt{root} и аутентификация по паролю намеренно оставлены
включёнными.

С прагматической точки зрения работа показала три вещи. Во-первых,
журналирование должно быть настроено до, а не после появления сервера в
сети: именно поэтому данные за первые часы позволили получить базовый
уровень «до» для лабораторной работы №4.2. Во-вторых, короткий базовый
период ненадёжен: журнал веб-сервера до запуска OSSEC охватывает всего 26
минут, и его нельзя использовать для количественного сравнения --
журналирование следовало запустить раньше, чем система защиты. В-третьих,
анализ журналов даёт прямые рекомендации: запретить вход \texttt{root},
отключить пароли в пользу ключей и автоматизировать реакцию на
повторяющиеся источники -- реализовано и оценено в отчёте по
лабораторной работе №4.2.
