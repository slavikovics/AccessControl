\labpart{Краткое описание веб-сервера}

\texttt{Caddy} -- веб-сервер, который сам получает и продлевает
TLS-сертификаты Let's Encrypt. Он раздаёт собранную React-страницу по
HTTPS, перенаправляет HTTP на HTTPS (ответ \texttt{308}) и пишет каждый
запрос одной JSON-строкой в \texttt{/var/log/caddy/access.log}.
Конфигурация (\texttt{Caddyfile}) и скрипты развёртывания лежат в
репозитории в каталоге \texttt{Lab4.1-WebServer}.

\labpart{Краткое описание анализируемых файлов}

\begin{itemize}
  \item \textbf{\texttt{/var/log/auth.log}} -- журнал аутентификации
  Ubuntu. Демон \texttt{sshd} пишет в него каждую попытку входа:
  \texttt{Accepted publickey/password} или \texttt{Failed password}, с
  именем пользователя, IP-адресом и временем.
  \item \textbf{\texttt{/var/log/caddy/access.log}} -- журнал доступа
  Caddy: IP клиента, метод, путь, код ответа, \texttt{User-Agent}. По путям
  вроде \texttt{/.env} и \texttt{/.git/config} видно автоматические
  сканеры.
\end{itemize}

Перебор идёт круглосуточно, без дневного профиля, то есть это
автоматические боты. В основном подбирают пароль \texttt{root}, остальные
имена -- стандартный словарь служебных учётных записей. Ни один из этих
адресов не вошёл в систему, но только потому, что пароль \texttt{root}
оказался стойким: вход \texttt{root} по паролю был разрешён.

\textbf{Веб-сервер, 5 сентября -- 8 октября (33 суток).} Результаты в
\autoref{lst:analysis-web}.

\begin{itemize}
  \item Всего 3\,539 запросов с 217 адресов; 2\,930 из них (83\,\%) --
  \texttt{404}, настоящих загрузок страницы только 284 (\texttt{200}), и
  30 запросов сделал сам администратор.
  \item Первый запрос пришёл в 18:49:54, в день запуска сервера, причём
  по доменному имени, а не по IP. Вероятно, адрес сканеры узнали из
  журналов Certificate Transparency, куда попадает каждый сертификат
  Let's Encrypt.
  \item Самые частые \texttt{404}: \texttt{/robots.txt},
  \texttt{/.git/config}, \texttt{/.env}, \texttt{/.env.production},
  \texttt{/phpinfo.php} -- поиск забытых файлов с паролями и ключами.
  \item Трафик идёт «пачками»: восемь адресов из диапазонов
  \texttt{34.x} и \texttt{35.x} (облачный хостинг) сделали по 277
  запросов каждый (2\,216 из 3\,539, 63\,\%); в самый активный день,
  21 сентября, было 842 запроса, в большинство дней -- единицы.
  \item Часть запросов -- от известного сканера LeakIX
  (\texttt{User-Agent} с \texttt{l9scan}).
\end{itemize}

\labpart{Рекомендации по улучшению безопасности удалённого сервера}

\begin{enumerate}
  \item Запретить вход \texttt{root} по SSH (\texttt{PermitRootLogin no}),
  работать через обычного пользователя и \texttt{sudo}.
  \item Отключить вход по паролю (\texttt{PasswordAuthentication no}) и
  оставить только ключи: тогда подбор пароля бесполезен.
  \item Разрешить SSH только с известных адресов (например, из VPN) или
  закрыть порт 22 на firewall.
  \item Поставить систему защиты, которая блокирует источники перебора
  автоматически (см. отчёт №4.2).
  \item Не хранить в корне сайта файлы \texttt{.env}, \texttt{.git}
  и подобные -- их ищут в первую очередь.
\end{enumerate}
